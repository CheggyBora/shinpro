# Календарь задач, контрагенты, склад и покраска

Договорённость с владельцем от 24.10.2026. Макеты:
https://claude.ai/artifact/8UPhwDX3twamJyrpaQkq3c

## Что и где

- **Календарь** — пункт главного меню цеха (после «Записи») и раздел
  дашборда. Неделя сверху, задачи выбранного дня ниже. Задачи из цеха,
  из дашборда, со склада, из покраски и из кабинета клиента — одни и те же.
- **Разделы задач** (в этом порядке): Рабочая (`work`), Хранение
  (`storage`), Шины (`tires`), Покраска (`paint`). Фильтр — эти четыре
  и «Все». У каждого свой цвет, одинаковый везде.
- **Задача**: раздел, дата, время (может не быть), машина (номер —
  открывает «всё по машине»), контрагент, заголовок, что сделать, сумма
  (для покраски). Править можно всё; перенос: +1 час, завтра, через
  неделю, любая дата. «Сделано» — отметка с именем и временем.
- **Напоминания без окон**: лента задач на сегодня над нарядами (скоро —
  жёлтая, просрочено — красная); неотмеченная задача прошлых дней
  остаётся в ленте красной, пока её не отметят; задача про машину
  показывается в наряде этой машины. Владельцу — сводка в Telegram утром
  и вечером (сервер). Передачи смены нет.
- **Контрагенты** — раздел в «Настройках» цеха: название, чем занимается,
  контакт, телефон, почта, адрес, ИНН, заметка.
- **Хранение из наряда**: кнопки «Принять на хранение» / «Выдать с
  хранения» в шапке наряда открывают привычные формы вкладки «Хранение
  шин», заполненные из наряда и клиента: номер, клиент, телефон,
  водительское удостоверение, вид транспорта, диаметр.
- **Водительское удостоверение** — новое поле клиента.
- **Склад**: приём на хранение ставит задачу «Отвезти на склад», «Заказать
  со склада» во вкладке хранения — «Привезти со склада» к дате и времени;
  то же — когда клиент заказал комплект из кабинета. Сообщение в Telegram.
- **Покраска**: в калькуляторе — машина (как в нарядах), «готово к»,
  «Оформить покраску» → задача «Покраска» с суммой и сообщение в Telegram.
- **Telegram**: получатели настраиваются по видам сообщений (склад,
  покраска, сводка); по умолчанию — те же, что для сводки по смене. Без
  интернета сообщение ждёт и уходит, когда связь вернётся.

## Данные и обмен

Задача (`calendar_tasks` в цеху, `tasks` на сервере):

| Поле | Что |
|---|---|
| `uid` | uuid4 строкой — одна и та же задача в цеху и на сервере |
| `category` | `work` / `storage` / `tires` / `paint` |
| `due_date` | `YYYY-MM-DD` |
| `due_time` | `HH:MM` или пусто |
| `title` | коротко, что это (≤200) |
| `note` | что сделать |
| `license_plate` | номер машины или пусто |
| `client_name`, `client_phone` | для показа там, где клиента нет в базе |
| `counterparty_uid` | контрагент или пусто |
| `storage_ref` | номер комплекта хранения (номер в цеху) или пусто |
| `amount` | сумма (покраска) или пусто |
| `done_at`, `done_by` | когда и кто отметил «сделано» |
| `deleted` | удалена (строка остаётся, чтобы удаление дошло до второй стороны) |
| `source` | `shop` / `dashboard` / `auto` / `cabinet` |
| `created_by` | кто поставил (имя) |
| `created_at`, `updated_at` | ISO, московское время |

Контрагент (`counterparties`): `uid`, `name`, `kind`, `contact`,
`phone`, `email`, `address`, `inn`, `note`, `deleted`, `updated_at`.

**Обмен** `POST /sync/tasks` (ключ точки, как прочий `/sync`):

```
→ {"since": "<ISO или null>", "tasks": [...изменённые в цеху...],
   "counterparties": [...изменённые в цеху...]}
← {"now": "<ISO>", "tasks": [...изменённые на сервере после since...],
   "counterparties": [...]}
```

Правило слияния — побеждает более поздний `updated_at` (при равенстве —
сервер не трогает). Сервер в ответ отдаёт строки с `updated_at > since`,
включая только что принятые (цех спокойно перезапишет их тем же).
Цех запоминает `now` как следующий `since`. Обмен идёт вместе с живой
очередью, раз в 20 секунд, — задача из дашборда появляется в цеху сразу.

Настройки, которые цех присылает серверу обычным обменом:
`telegram_chats_storage`, `telegram_chats_paint`, `telegram_chats_digest`
(через запятую; пусто — общие `telegram_chats`), `task_digest_morning`
(`09:00`), `task_digest_evening` (`20:00`), `task_digest_enabled` (`1`).

## Мойка: свой слой календаря (26.10.2026)

Объект может работать и шиномонтажом, и мойкой (services/directions.py).
У мойки свой календарь и свои контрагенты — отдельный слой:

- У задачи и контрагента новое поле `direction`: `tire` (по умолчанию,
  всё, что было раньше) или `wash`.
- Разделы задач зависят от направления. Шиномонтаж: Рабочая (`work`),
  Хранение (`storage`), Шины (`tires`), Покраска (`paint`). Мойка: Рабочая
  (`work`), Поставки (`supply`). Фильтр «Все» — у каждого слоя свой.
- В цеху календарь, лента задач над нарядами и выбор контрагента в задаче
  показывают слой того направления, что выбрано переключателем сверху.
  Новая задача получает это направление.
- Контрагенты в Настройках — с переключателем «Шиномонтаж | Мойка», если
  мойка включена.
- В дашборде — тот же переключатель в календаре, если на точке включена
  мойка (настройка точки `direction_wash`, приходит обычным обменом).
- Обмен `/sync/tasks` передаёт `direction` у задач и контрагентов.
  Старый цех его не присылает — значит `tire`.
- Сводка владельцу в Telegram: задачи мойки помечены «Мойка:».
