## Настройки организации — из программы в дашборд

Решение владельца 29.10.2026: «пока не делаем, но не забыть».

Сейчас часть настроек всей организации живёт в программе на точке и
уезжает на сервер обменом. Сервер берёт их у **первой точки
организации**. Пока точка одна — работает; при двух и больше ключ,
вписанный во второй точке, молча не действует.

1. **Ключи входа: звонок (flashcall.ru) и SMS (sms.ru)** → дашборд,
   раздел «Организация», только владелец. Хранить у организации, а не
   у точки. В программе вместо полей — «настраивается в дашборде».
   Сейчас: программа → Настройки → «SMS и звонки»; сервер —
   `app/services/callcheck.py`, `sms.py` (`setup()` берёт `call_token`,
   `sms_key` из настроек точки), `staff_service._shop()` /
   `auth_service._shop()` — первая точка аккаунта.
2. **Telegram-бот — один на организацию, им управляет сервер.**
   - Токен бота вписывается в дашборде.
   - Кто нажал «Старт», видит сервер (сейчас — программа через
     `getUpdates`; две точки с одним ботом отбирают друг у друга
     обновления, и люди пропадают из списка).
   - Все отчёты рассылает сервер: программа передаёт ему готовую сводку
     по смене, склад, покраску, задачи — он шлёт людям из «Доступа» и
     прочим получателям.
   - Делать вместе с обновлением программы на точке.
   Сейчас: программа — `services/telegram_service.py`,
   `services/telegram_outbox.py`; сервер — `app/services/notify.py`
   (токен и чаты приходят из настроек точки), `telegram_usernames`
   (ник → чат) присылает программа.
3. **В программе остаётся только своё у точки:** часы работы, посты,
   прайс, печать, касса, склад, режим приёма машин.
