# Другие организации на нашем сервере

Решение владельца 27.10.2026: программу продают другим организациям. У
каждой свой сайт записи, свой кабинет клиента и свой дашборд — под её
названием и логотипом. Сервер один на всех.

## Адреса

| Адрес | Что открывает |
|---|---|
| `lk.rif-service.ru`, `admin.rif-service.ru` | запись и дашборд того, кто держит сервер («РИФ») |
| `koleso.rif-service.ru` | запись и кабинет «Колеса» — появляется сразу при заведении |
| `koleso-admin.rif-service.ru` | дашборд «Колеса» |
| `zapis.koleso.ru`, `admin.koleso.ru` | свои домены «Колеса», подключает сам владелец в «Оформлении» |

Чей кабинет открыт, сервер узнаёт по адресу (`tenancy.host_target`).
Точку чужой организации на своём адресе не открыть, вход в чужой
дашборд не пройдёт даже с тем же телефоном.

Домашние адреса берутся из `SERVER_CORS_ORIGINS` (их пишет install.sh),
домен для организаций — из них же: `lk.rif-service.ru` → `rif-service.ru`.
Переопределить можно `SERVER_HOME_HOSTS`, `SERVER_PLATFORM_DOMAIN`,
`SERVER_HOME_ACCOUNT`.

Имена `lk`, `admin`, `www`, `api` и подобные организация получить не
может, как и имя на `-admin` (это чужой дашборд).

## Что нужно один раз

У регистратора `rif-service.ru` — запись `*` типа A на адрес сервера.
Тогда любой `что-угодно.rif-service.ru` ведёт к нам, и новые
организации получают адрес без участия человека.

## Как адрес начинает работать

Раз в 5 минут таймер `tire-domains` (deploy/domains.sh, от root):

1. спрашивает базу, какие адреса должны работать (`manage.py domains-plan`);
2. свои домены организаций вписывает в `/etc/nginx/tire/*-names.conf`;
3. для адреса, который уже смотрит на сервер, выпускает сертификат
   (certbot, проверка через `/var/www/tire-acme`);
4. для адреса с сертификатом пишет блок https в `/etc/nginx/tire/sites/`;
5. перезагружает nginx, а статус («Работает», «Ждём запись») пишет в базу —
   его видно в дашборде.

nginx не принял новые файлы — они откладываются, и lk./admin. не падают.
Сертификат не выпустился — повтор через час.

## Оформление

Дашборд → «Оформление»: название, логотип (приводится к PNG 512×512 и
хранится в базе), цвет кнопок. Видно на странице записи, в кабинете, на
экране очереди и значком на телефоне. Без своего логотипа — никакого:
логотип «РИФа» другим организациям не показывается.

3D-схема парковки нарисована с площадки «РИФа», поэтому ссылка на неё
даётся только точкам «РИФа».

## Новый заказчик и новая точка — по коду

Решение владельца 27.10.2026: точки ставят люди, которые плохо
разбираются в компьютере, поэтому ни SSH, ни ключа обмена руками.

1. Дашборд → «Заказчики» (видит только номер `SERVER_OWNER_PHONE`) →
   «Новый заказчик»: название, короткое имя для адреса, телефон владельца,
   «оплачено до». Сервер заводит организацию, первую точку без ключа,
   владельца для входа в дашборд и выдаёт код из 8 цифр с готовым
   сообщением.
2. Сообщение пересылается установщику. В нём ссылка на страницу
   скачивания: `setup.ДОМЕН`, пока у него нет сертификата — `lk.ДОМЕН/setup`.
3. Программа скачивается только по действующему коду. Скачивание код не
   тратит.
4. В программе цеха: Настройки → «Приложение для клиентов» → «Подключить
   по коду…». Программа получает ключ обмена сама (`POST /connect`), код
   погашен. Дальше владелец входит в дашборд по своему номеру.

Код живёт 48 часов и срабатывает один раз; новый код точки отменяет
прежний. Десять неверных кодов с одного адреса — пауза 15 минут.
Переподключить компьютер: «Точки» → «Переподключить» (владелец
организации сам) — старый компьютер работает, пока код не введут на
новом. Из консоли: `manage.py connect-code ИМЯ_ТОЧКИ`.

Новую версию программы загружают в «Заказчики» → «Программа для точек»:
файл режется на куски по 4 МБ (nginx пускает до 10 МБ), сервер
проверяет, что это .exe, и кладёт в `downloads/` — раскатка эту папку не
стирает.
