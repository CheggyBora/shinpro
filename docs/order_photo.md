# Наряд по фото машины

Решения владельца от 26.10.2026 (макет https://claude.ai/artifact/EJhboExHfhDVPVxUkDvDu7, экраны 1–4).

## Как работает

1. В цеху рядом с «Создать наряд» кнопка «QR». Это тот же пропуск телефона, что у фото мастеров
   (`/m`, `MasterDevice`): раз отсканировал — телефон запомнил.
2. На странице телефона кнопка «Новая машина»: камера → снимок уходит на сервер → сервер
   распознаёт номер (на своём сервере, без облака) → телефон показывает номер (можно поправить),
   «есть в базе: …», «записан на 14:30 · шиномонтаж», выбор Шиномонтаж/Мойка/Оба (только когда
   у точки включена мойка) → «Создать наряд».
3. Цех при ближайшем живом обмене (каждые 20 с) получает «машину с телефона» и открывает обычное
   окно создания наряда: номер, клиент, диаметр с прошлого визита подставлены, сбоку фото.
   Создаёт наряд приёмщик. Создал — фото становится обложкой наряда. Закрыл окно — машина
   снимается (не всплывает снова).
4. Номер не прочитался — поле пустое, вписывают руками; фото всё равно станет обложкой.

## Включение

Наряд по фото включается отдельно для шиномонтажа и мойки. Цех шлёт в `settings` обмена
`arrival_photo_tire` и `arrival_photo_wash` (`'1'`/`'0'`; пусто или нет — выключено). Мойка
учитывается, только если у точки включена сама мойка (`direction_wash`).

- Ни одно не включено — «Новой машины» на телефоне нет, `/m/arrival/recognize` отвечает 400.
- Включено одно — выбора направления на телефоне нет, уходит это направление.
- Включены оба — выбор Шиномонтаж / Мойка / Оба.
- `POST /m/arrival` с выключенным направлением — 400 с причиной по-русски; без `directions` —
  первое включённое.
- Обложки в дашборде показываются всегда, когда они есть.

## Обложка — во всех четырёх местах

А — шапка наряда (миниатюра, щелчок — на весь экран); Б — вкладки открытых нарядов;
В — «Всё по машине» (последнее фото крупно) и у каждого визита; Г — дашборд (список нарядов и
карточка наряда).

## Обмен

Телефон (пропуск мастера в cookie/заголовке, как у `/m/photo`):

- `POST /m/arrival/recognize` — multipart `photo` → `{"photo_id", "plate" | null, "known":
  {"client_name", "car", "last_visit"} | null, "appointment": {"time", "direction"} | null,
  "wash_enabled": bool}`. Снимок сохраняется как `OrderPhoto` без наряда (`kind='cover'`).
  Сверх этого в ответе: `"directions_allowed": ["tire", "wash"]` — включённые направления (по
  ним телефон рисует выбор), `"plate_complete": bool` — номер полный или только основная часть
  без региона («А123ВВ», регион не прочитался и в базе по основной части не нашлось одной машины),
  `"confidence"` — уверенность распознавания 0…1.
- `POST /m/arrival` — `{"photo_id", "plate", "directions": ["tire"] | ["wash"] | ["tire","wash"]}`
  → `{"ok": true, "arrival_id"}`. Номер обязателен, приводится к виду А123ВВ777 (латиница,
  похожая на кириллицу, → кириллица). Строгий российский формат не требуется: приезжают и
  машины с номерами других стран.
- `POST /m/arrival/hints` — `{"plate"}` → `{"known", "appointment"}`: подсказки для номера,
  поправленного руками. `GET /m/cars` дополнительно отдаёт `arrival_directions`.

Цех (ключ обмена):

- `GET /sync/arrivals` → `{"arrivals": [{"id", "plate", "directions", "photo_id",
  "created_at"}]}` — ждущие, не старше 2 часов.
- `GET /sync/arrivals/{id}/photo` → JPEG.
- `POST /sync/arrivals/{id}/done` — `{"order_local_id": 1243 | null}`. С номером наряда — фото
  привязывается к наряду как обложка (`order_local_id`, `kind='cover'`); `null` — приёмщик
  закрыл окно, машина снимается.

Дашборд: у наряда (список и карточка) поле `cover_url` — адрес снимка для вошедшего сотрудника.
Ссылка подписана и живёт полдня (`/dashboard/photo/{id}?until=…&key=…`): картинку грузит `<img>`,
заголовок с токеном туда не положить.

Обложка (`kind='cover'`) клиенту не уходит, в его кабинете и в `GET /sync/photos` (снимки мастеров
по наряду) её нет.

## Распознавание на сервере

`server/app/services/plates.py`: fast-alpr (ONNX, процессор) — детектор
`yolo-v9-t-384-license-plate-end2end` и чтение `cct-s-v2-global-model`. Российской модели нет:
модель «global» читает латиницу, буквы переводятся в кириллицу и проверяются по форматам
(обычный, такси, прицеп). Модели грузятся один раз на рабочий процесс при первом снимке,
~140 МБ памяти на процесс (у службы два процесса — до ~280 МБ). Веса (~13 МБ) скачиваются
один раз в `SERVER_PLATE_MODEL_DIR` (по умолчанию `/opt/tire-server/plate-models`, служба
пишет туда сама; раскатка папку не стирает), заранее — `manage.py plate-models` (его вызывает
`deploy/update.sh`). Выключить — `SERVER_PLATES=0`. Каждый снимок пишется в журнал:
`plates: А123ВВ777 in 840 ms`.

## Цех

- `WorkOrder.cover_path` — путь к файлу обложки в папке программы (`photos/covers/<id>.jpg`).
- «Всё по машине» берёт последнюю обложку нарядов машины.
